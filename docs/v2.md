# vibe-idx v2

vibe-idx supports a daily workflow. Scan ownership and trading anomalies, open a ticker, inspect broker flows and public reports, then read its news.

## Runtime

GitHub Actions runs the IDX TypeScript batch, and one collector machine runs the broker batch. DuckDB reads private Parquet history and writes public website JSON. Vercel serves the React application and its request handlers.

Shared links include a default Vibe IDX preview. Ticker links receive server-rendered metadata with the company name, latest close, daily change and reporting date. `/api/og` renders the price card from public ticker data; its dated image URL refreshes chat previews each session. Vercel injects the metadata before serving the SPA, and the preview Worker does the same using the public bucket. The Worker proxies image rendering to Vercel. Missing ticker data falls back to the default preview so the page can still load.

`apps/pipeline/ingest.ts` collects prices, indices, issuers, monthly 1% holders, daily 5% reports, and paginated disclosures. `reports.ts` extracts supported insider and registry PDF fields. `sql.ts` defines the tables and website projections. Pure source parsers and their fixtures live under `apps/pipeline/lib` and `fixtures`.

`apps/pipeline/brokers.ts` runs `brokerActivity.ts`, the only broker collector. It plans dates with positive-volume prices from January 1, 2026 through the latest session completed by 17:17 Jakarta. For each date, newest first, it lists active brokers separately on the Regular, Negotiation, and Cash boards. It fetches each broker's domestic and foreign client gross activity through `/order-trade/broker/activity`, following pagination and retaining Stockbit's historical share counts.

A Cloudflare Worker dispatches source ingestion through GitHub Actions daily at 17:17 Jakarta. Manual source ingestion refuses to start before 17:17 Jakarta. Broker collection runs on one machine under the `vibe-idx-collector` systemd user unit, back to back, each run bounded by `BROKER_DEADLINE_MINUTES` (240). Activity requests share a pace of 10 starts per second, configurable with `BROKER_ACTIVITY_RPS`. Completed targets resume without a source call.

The collector holds a `broker-run.json` marker for the run, which expires 15 minutes after the run's deadline. Markers without an expiry, written by GitHub runs, expire six hours after they started. A run takes over only an expired marker, with `If-Match`. On its first source request, the collector refreshes authentication, saves the local rotated pair with mode 0600, and writes it to `auth/stockbit.json` with `If-Match`. If that save fails, it attempts `auth/stockbit-unsaved.json` for operator recovery. When Stockbit rejects the cloud pair with HTTP 401 or 403, it retries once with the local pair. R2 reads request identity encoding to preserve strong ETags. Authentication is shared across all activity requests in the run.

Activity rows and target completion commit together. Checkpoints upload changed activity years before coverage. A day-board is complete only after the broker list is fetched and every listed broker's domestic and foreign targets complete. After collection checkpoints, `brokers.ts` publishes regular-board concentration, then `publishBrokerActivity` publishes full ticker history since January 2026. It sums domestic and foreign shares and buy frequencies per broker for the existing 1-, 3-, and 5-session concentration windows. Missing or incomplete positive-volume sessions produce null windows. Ticker JSON retains the client split. Its publication manifest skips unchanged files and commits only after all changed uploads succeed.

Persistent request failures stop the phase. Invalid target responses remain pending and are reported after publication. A refresh revokes the previous pair immediately, so a lost refresh response may require a new token seed.

`apps/web/api/brokers.ts` verifies a WorkOS session JWT against the configured client's signing keys before it reads private R2. It returns JSON with private, no-store caching. `api/news.ts` fetches Google News RSS for a validated ticker and returns article metadata. Public market and ownership pages need no login.

The React AuthKit SDK owns PKCE, access-token renewal, and email-code login. This app uses WorkOS's documented mode without a custom authentication domain. The SDK stores its refresh token in browser local storage. Access tokens stay in SDK memory. A custom authentication domain can replace that storage mode later. R2 and Stockbit secrets never enter browser configuration.

## Storage

The private bucket, `vibe-idx-private`, holds these paths.

- `raw/` archives fetched IDX responses. Historical `raw/broker/` objects remain unused.
- `parquet/<table>/<year>.parquet` holds the historical tables. Issuers use one current file.
- `parquet/broker_activity/<year>.parquet` holds broker activity by board, broker, client domicile, and side.
- `parquet/broker-activity-coverage.parquet` records fetched day-board lists and target completion.
- `broker-run.json` keeps a second collector out until the holding run ends or its marker expires.
- `parquet/brokers/` and `parquet/broker-coverage.parquet` remain stored but are unused.
- `auth/stockbit.json` holds the rotated source token pair.
- `site/broker/<TICKER>.json.gz` holds complete broker activity since January 2026.
- `site/broker-activity-publication.json` holds hashes of the published ticker files.
- `site/market-accumulation.json` holds regular-board broker concentration windows.

The broker workflow restores only prices, broker activity years, and activity coverage. IDX ingestion restores only activity coverage for its freshness check and excludes activity from uploads. The latest complete broker session requires complete coverage on all three boards. A scheduled run starting or a partial checkpoint does not establish completion. No retirement step deletes stored objects.

The public bucket, `vibe-idx-public`, holds `health.json`, `market.json`, `feed.json`, `tickers.json`, and `ticker/<TICKER>.json`. Vercel maps `/data/*` to that bucket. Broker objects never enter it.

The broker endpoint accepts `GET /api/brokers?ticker=BBCA` with a WorkOS bearer token. It returns `{ticker, days}`. Each day has `date`, `board`, `buy`, and `sell`. Each broker row has `broker`, `investor`, `broker_type`, `shares`, `value`, `avg_price`, and `freq`. `investor` identifies domestic or foreign clients; `broker_type` identifies the broker category. The browser filters an inclusive date range, sums gross shares and values, and computes weighted average prices from value divided by shares. Broker flows do not establish beneficial ownership or current inventory.

## Public sources and dates

Prices and indices use IDX trading-summary endpoints on `www.idx.id`. Issuers use its company-profile endpoint. Ownership files come from the IDX shareholding-data list. Monthly 1% and daily 5% dates come from XLSX contents, not file publication timestamps. Duplicate monthly holder rows retain their sequence identity.

Disclosures use every page of `ListedCompany/GetAnnouncement`. The first collection covers 90 calendar days. Later runs overlap the latest stored publication date by two days to capture additions. Public output retains publication timestamps, source links, and attachments. Insider share changes use the report date. Registry values use the report's month-end date.

The supported KSEI insider layout provides the reporter and shares before and after the report. Their difference is a reported net change, not a reconstruction of every trade. Supported IDX registry layouts provide reported free float and SID counts. Unknown values remain null. Registry total shares need a verified table-layout parser and remain null. Unsupported layouts keep their original disclosure links and appear in the batch's `report_gaps` output.

The news endpoint returns titles, sources, dates, and links from a Google News search for the stock code and `saham`. It does not fetch article bodies. Stock-code matching can include unrelated articles.

## Deployment configuration

Set `VITE_WORKOS_CLIENT_ID` for the browser build. Set `WORKOS_CLIENT_ID`, `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, and `R2_SECRET_ACCESS_KEY` for the Vercel functions. Use a private-bucket read credential for the web app. The pipeline has separate write credentials in GitHub Actions.

In WorkOS, enable Magic Auth and configure the deployment's exact origin, `/callback` redirect, root sign-out URI, and `/login` initiate-login URI. Match staging and production client IDs to their deployment settings.

Repository cleanup removes the old Convex, SQLite, Python, and Docker runtime. It does not delete cloud projects or stored data. Inspect the old Convex deployments before retiring their hosted schedules.
