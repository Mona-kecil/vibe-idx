# vibe-idx v2

vibe-idx is an IDX anomaly radar. It is a personal daily tool, public without login.

The daily workflow it serves:

1. Scan 5% ownership changes for anomalies.
2. Scan price and volume for anomalies (abnormal volume, ARA, green while the market is red).
3. Deep-dive a ticker: free float, holder composition, broker summary, insider trades.
4. Read the ticker's news and IDX disclosures without searching by hand.

## Architecture

Convex owns the database, the scheduler (crons), and all ingest (Node actions).
Vercel hosts the React frontend only. The UI ships in Indonesian and English.

There is no Python, no Docker, and no browser impersonation. Every IDX endpoint
is fetched with plain `fetch` from the `www.idx.id` host. The `www.idx.co.id`
host sits behind Cloudflare and returns 403 to datacenter IPs.

## Data model

Storage targets the Convex free plan (0.5 GB). The 5% file has about 3,000
account rows per day, so v2 stores the current holdings once and keeps history
only for investors whose holdings changed.

- `issuers` holds one document per ticker with name, board, sector, and aliases for news matching.
- `dailyPrices` holds one document per ticker per trading day.
- `indexDaily` holds one document per index per trading day.
- `fivePctHoldings` holds the latest state per ticker and investor, with its accounts nested.
- `fivePctChanges` holds one document per ticker, investor, and date where any account changed.
- `onePctHoldings` holds every row of each monthly 1% file.
- `announcements` holds IDX disclosures with ticker, title, time, and attachments.
- `insiderReports`, `registryReports`, `umaEvents`, and `suspensions` hold the parsed disclosure types.
- `ingestJobs` is the ledger that makes every ingest idempotent.

## Ingest

Each source has a discovery step and a job step. Discovery lists what exists
upstream and enqueues one job per unit of work (a date, a file, a PDF).
A job's key is the source plus the upstream identity, so enqueueing twice is a
no-op. A job moves `pending → running → done | failed`, and a failed job retries
with backoff up to a fixed attempt limit.

Parsers are pure TypeScript functions over bytes or JSON. They have no Convex
imports, so tests run them against real IDX fixtures. Writes go through internal
mutations in batches small enough for Convex transaction limits, and every write
is an upsert on the natural key.

Raw files are not archived. A job records the source URL and a content hash.
