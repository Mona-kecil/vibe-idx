# vibe-idx v2

vibe-idx supports a daily workflow. Scan ownership and trading anomalies, open a ticker, inspect broker flows and public reports, then read its news.

## Runtime

GitHub Actions runs one TypeScript batch. DuckDB reads private Parquet history and writes public website JSON. Vercel serves the React application and two request handlers.

`apps/pipeline/ingest.ts` collects prices, indices, issuers, monthly 1% holders, daily 5% reports, and paginated disclosures. `reports.ts` extracts supported insider and registry PDF fields. `sql.ts` defines the tables and website projections. Pure source parsers and their fixtures live under `apps/pipeline/lib` and `fixtures`.

`apps/pipeline/brokers.ts` collects complete Stockbit gross summaries for positive-volume price pairs from June 1, 2026 through the latest completed trading day. It processes newest dates first and replays archived raw responses before fetching missing pairs. It keeps completed pairs, including empty successful results. Buyer and seller counts must match the upstream totals.

One workflow queue serializes restore, source publication, and broker collection. The daily 17:17 Jakarta slot and manual launches run IDX ingestion before brokers. Eleven broker-only slots complete a two-hour cadence without fetching IDX sources. Each broker run stops at 50 minutes or 500 Stockbit attempts, including auth. Request starts are spaced by at least six seconds, including the first call. This ceiling does not establish a permitted Stockbit quota. Idle backfill runs make no Stockbit call; daily runs maintain auth.

The collector owns cloud token rotation, immutable raw writes, broker Parquet checkpoints, and private JSON publication. It acquires a persistent `broker-run.json` marker before reading the cloud token. It conditionally saves the rotated token and reads it back before the next provider request. Raw bytes receive create-once storage and readback before parsing or another request. Rows and pair completion commit together. Periodic checkpoints publish broker years before coverage, then serving JSON. Source uploads exclude broker Parquet.

The first error stops collection and retains the marker, blocking future broker attempts. A normal bounded or complete run clears it after publication. Daily public IDX ingestion can still run when brokers are blocked. Recovery requires operator review of the failed run, active writers, token state, and ambiguous cloud operations before marker removal; marker age grants no ownership. Provider token rotation and R2 persistence cannot form one atomic transaction, so a lost refresh response may require a new token seed. Manual launches test R2 create-once writes, rejected ETag conflicts, conditional updates, and readback before collector activation.

`apps/web/api/brokers.ts` verifies a WorkOS session JWT against the configured client's signing keys before it reads private R2. It returns JSON with private, no-store caching. `api/news.ts` fetches Google News RSS for a validated ticker and returns article metadata. Public market and ownership pages need no login.

The React AuthKit SDK owns PKCE, access-token renewal, and email-code login. This app uses WorkOS's documented mode without a custom authentication domain. The SDK stores its refresh token in browser local storage. Access tokens stay in SDK memory. A custom authentication domain can replace that storage mode later. R2 and Stockbit secrets never enter browser configuration.

## Storage

The private bucket, `vibe-idx-private`, holds these paths.

- `raw/` archives fetched IDX and Stockbit responses.
- `parquet/<table>/<year>.parquet` holds the historical tables. Issuers use one current file.
- `parquet/broker-coverage.parquet` records broker pair completion and pending work.
- `auth/stockbit.json` holds the rotated source token pair.
- `broker-run.json` blocks concurrent or unreviewed broker continuation.
- `site/broker/<TICKER>.json` holds the last 90 calendar days of collected broker summaries.

June history remains durable in raw responses and Parquet even when it falls outside the 90-day serving window. Backfill completion requires every eligible price pair in the requested range to be complete in the private ledger; a scheduled run starting or a partial checkpoint does not establish completion.

The public bucket, `vibe-idx-public`, holds `health.json`, `market.json`, `feed.json`, `tickers.json`, and `ticker/<TICKER>.json`. Vercel maps `/data/*` to that bucket. Broker objects never enter it.

The broker endpoint accepts `GET /api/brokers?ticker=BBCA` with a WorkOS bearer token. It returns `{ticker, days}`. Each day has `date`, `buy`, and `sell`. Each broker row has `broker`, `investor_type`, `shares`, `value`, `avg_price`, and `freq`. The browser filters an inclusive date range, sums gross shares and values, and computes weighted average prices from value divided by shares. Broker flows do not establish beneficial ownership or current inventory.

## Public sources and dates

Prices and indices use IDX trading-summary endpoints on `www.idx.id`. Issuers use its company-profile endpoint. Ownership files come from the IDX shareholding-data list. Monthly 1% and daily 5% dates come from XLSX contents, not file publication timestamps. Duplicate monthly holder rows retain their sequence identity.

Disclosures use every page of `ListedCompany/GetAnnouncement`. The first collection covers 90 calendar days. Later runs overlap the latest stored publication date by two days to capture additions. Public output retains publication timestamps, source links, and attachments. Insider share changes use the report date. Registry values use the report's month-end date.

The supported KSEI insider layout provides the reporter and shares before and after the report. Their difference is a reported net change, not a reconstruction of every trade. Supported IDX registry layouts provide reported free float and SID counts. Unknown values remain null. Registry total shares need a verified table-layout parser and remain null. Unsupported layouts keep their original disclosure links and appear in the batch's `report_gaps` output.

The news endpoint returns titles, sources, dates, and links from a Google News search for the stock code and `saham`. It does not fetch article bodies. Stock-code matching can include unrelated articles.

## Deployment configuration

Set `VITE_WORKOS_CLIENT_ID` for the browser build. Set `WORKOS_CLIENT_ID`, `R2_ACCOUNT_ID`, `R2_ACCESS_KEY_ID`, and `R2_SECRET_ACCESS_KEY` for the Vercel functions. Use a private-bucket read credential for the web app. The pipeline has separate write credentials in GitHub Actions.

In WorkOS, enable Magic Auth and configure the deployment's exact origin, `/callback` redirect, root sign-out URI, and `/login` initiate-login URI. Match staging and production client IDs to their deployment settings.

Repository cleanup removes the old Convex, SQLite, Python, and Docker runtime. It does not delete cloud projects or stored data. Inspect the old Convex deployments before retiring their hosted schedules.
